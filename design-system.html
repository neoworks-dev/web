Neoworks Design System

A unified visual language for all Neoworks apps. Built for clarity, accessibility, and warmth — so every app feels like part of the same family.

01
One base, one accent
Every app shares the exact same base tokens — backgrounds, text, borders, spacing, type. The only thing that differs between apps is a single accent color. This creates immediate coherence: users moving between Grove and Tide recognize the same interface skeleton instantly.
02
Accessibility first
All text colors meet WCAG AA at minimum (4.5:1 for body copy, 3:1 for large text and UI elements). App accents are chosen to pass contrast on white surfaces. Focus states are always visible. The system never sacrifices legibility for aesthetics.
03
Warm, not clinical
The base palette uses warm-tinted neutrals — a small yellow/brown shift away from pure gray. This prevents the cold, sterile feeling of blue-gray systems (like many SaaS products) and makes long reading sessions more comfortable. Backgrounds breathe; text doesn't strain.
04
Quiet until needed
Accents appear sparingly — on primary actions, active navigation states, and focus elements. The rest of the UI is base colors. This preserves the visual weight of the accent so it always signals "this matters" — rather than competing with itself everywhere.

Colors

Base palette + per-app accents. The base never changes across apps. Accents are the single differentiator per app.

The one-accent rule

◈
Each app uses exactly four accent-derived values: {app}-fg for text/icons, {app}-accent for filled interactive elements, {app}-subtle for tinted backgrounds, and {app}-border for accented borders. Never reference another app's tokens. Never introduce a second accent per app.

When to use the accent

Element Token to use Example
Primary button background {app}-accent Save, Submit, Create
Active nav item {app}-fg for text + {app}-subtle for bg Sidebar active link
Accented badge/tag {app}-subtle bg + {app}-fg text + {app}-border border Status pill, category tag
Progress bar fill {app}-accent Upload progress, completion
Focus ring --border-focus (always base, never accent) Any focused input/button
Link text {app}-fg Inline links
Icon in active state {app}-fg Nav icon, checkbox icon
Checkbox/radio checked {app}-accent fill Form controls

Accent color specifications

All -fg values pass WCAG AA (4.5:1) on white. All -accent values pass WCAG AA on white for use as button backgrounds with white text.

Buttons

Four variants, three sizes. The filled style uses the app accent. All other variants are base-color only.

→
Only use the filled variant for the single primary action on a page or in a panel. Use outlined or ghost for secondary actions. Never place two filled buttons next to each other — it creates visual noise and dilutes the accent.

Filled — primary action (uses app accent via style prop)

Background: {app}-accent · Text: white · Hover: 88% opacity

Outlined — secondary action

Background: transparent · Border: --border-strong · Text: --text-primary

Ghost — tertiary / icon actions

Background: transparent · No border · Text: --text-secondary → primary on hover

Danger — destructive actions

Background: --status-error-bg · Text: --status-error-fg. Always confirm before firing.

Forms

Inputs, selects, textareas, checkboxes, and toggles. All share the same base border and focus styles. Accents are only used in checkboxes and the checked toggle state — and only through the app's own accent token.
